# 第三步：素材与全模态引用

2026-10-03：视频生成链路已接入，当前实现和验收见 [第二阶段记录](./reference-generation.md)。以下是此前素材准备阶段的历史记录。

2026-10-02：本阶段已完成并验证。支持 WAV / MP3 上传、音频播放与进度控制、视频节点混合引用图片 / 视频 / 音频、分类编号、参考规则提示，以及保存与刷新恢复。视频生成任务接口仍待实现，当前视频面板没有生成按钮。

## 操作与数据流

右键上传素材 → 本地预览 → 保存画布节点 → `POST /api/assets` → 后端校验文件头、大小并读取媒体参数 → 私有 OSS 保存文件 → PostgreSQL `assets.metadata` 登记资源 → 前端显示保存结果。

视频节点点击“参考”，按选择顺序记录 `referenceIds`。例如图片、视频、图片、音频显示为图片1、视频1、图片2、音频1；缩略图和连线都由同一组 ID 派生，不重复保存一份连线数据。移除引用不删除源素材，但会重新编号。手写普通文本中的编号仍需自行检查；2026-10-02 新增的结构化 `@` 图片／视频标签绑定节点 ID，编号变化不会改变来源，引用被移除时显示失效，详见 [提示词引用第一阶段](./prompt-mentions.md)。

刷新 → 从画布快照恢复节点、草稿、引用 ID → 从 assets 恢复持久化资源及服务端媒体参数 → 经 `/api/assets/content?key=...` 读取私有文件 → 恢复播放和引用检查。音频没有生成 / 提示词入口，不能作为图片节点的参考。

## 文件契约与校验职责

- `GET /api/storage/config` 新增 `maxAudioBytes: 15000000`。
- `asset.kind` 增加 `audios`；路径为 `.../uploads/audios/<nodeId>/<assetId>.wav|mp3`。
- `asset.media` 按类型包含 `width`、`height`、`durationSeconds`、`frameRate`、`videoCodec`、`audioCodec`。时长保留小数精度，图片不伪造时长，音频不伪造像素尺寸。
- `asset.videoReference` 包含 `eligible` 和不合格时的 `reason`，由后端基于真实文件参数生成。它表示单份素材符合参考条件，不表示已通过方舟接口验证。
- 单文件校验：图片 PNG/JPEG/WebP/GIF/BMP ≤20 MiB；视频 MP4/MOV ≤200000000 字节，H.264/H.265、24～60 fps；音频 WAV/MP3 ≤15000000 字节。参考音视频单段 2～30 秒，图像尺寸和视频像素数按 [视频契约](./video-generation-contract.md) 校验。
- 前端合并校验：至少 1 项；图片≤30、视频≤10、音频≤10；视频与音频分别合计≤30秒，不能先取整；检查保存状态、类型、所属画布 / 节点及重复 Key。

**可播放不等于可供模型参考。** 比如旧测试 MP4 为 320×240 / 12 fps，可以存储、播放和保留引用草稿，但会显示参考不合格。前端校验用于反馈；下一阶段的视频提交接口仍须从数据库读取资产并重新校验，不能信任客户端声明或只依赖按钮状态。

音视频上传依赖后端可执行的 `ffprobe`：优先使用 `FFPROBE_PATH`，留空使用 PATH。本机已安装并验证。通过独立进程读取参数，不调用 shell，不传入用户命令；限制 10 秒、256 KiB 输出并仅允许本地文件协议。缺失工具或文件损坏时不写 OSS，保留浏览器本地预览并允许重试。FFmpeg 仅用于重新制作测试文件，日常上传只需 ffprobe。

旧资源缺少服务端元数据时显示“重新上传以校验视频参考要求”，仍可按原功能预览。**本阶段没有后台回填旧资产**；契约中的后台预检属于后续视频任务阶段。已保存素材暂时预览失败时保留引用关系；没有保存过的损坏本地素材按原有规则清理引用。

沿用 `canvases.snapshot` 与 `assets.metadata` 的 JSONB 字段，本阶段没有新增数据库表或迁移，也没有引入 Redis / MQ。文件保存与数据库登记仍按既有流程执行，未增加孤立 OSS 对象清理能力。

- 40 项既有浏览器回归通过；8 项新增专项通过，覆盖 WAV/MP3 播放、进度、播放不误选、音频不能被图片引用、混合编号 / 移除 / 窄屏、失败重试、数量和时长边界、旧元数据、重复 Key 与归属错误。
- `go test -count=1 -timeout 60s ./...`（设置独立测试库 `TEST_DATABASE_URL`）和 `go vet ./...` 通过。新增用例读取实际测试文件并运行 ffprobe，使用内存对象存储检查字节不变；真实 PostgreSQL 用例验证音频元数据和引用恢复。
- `npm run build` 通过。
- 真实浏览器 → Go → PostgreSQL / OSS 通过：上传 PNG、MP4、WAV、MP3；所有文件读取 SHA-256 一致；三份音视频均通过 206 Range 校验；刷新后草稿、引用、播放和进度控制恢复；页面无运行错误，生成请求为 0。
- 证据：`frontend/artifacts/media-references-live.json`、同名 PNG（本地产物，不进 Git）。验收画布 ID 为 `5be2358d-275a-443d-ae54-6660d3b2bae3`。一次早期验收脚本因浏览器响应缓存失效中断；修正响应捕获后完成，未触发模型调用。

复验真实存储时，在已启动前后端的情况下，于 `frontend/` 执行：

```powershell
$env:RUN_LIVE_MEDIA_REFERENCES = '1'
node scripts/verify-live-media-references.mjs
```

脚本会新建验收画布并上传四份自制素材，拦截生成请求，不读取模型 / OSS 凭据。一般回归仍使用模拟接口，不产生云上传。素材复现脚本是 `scripts/create-reference-fixtures.ps1`。

## 本阶段边界与工程理解

本次完成的是生成前的素材与引用准备，**供应商视频接口、异步视频任务、结果转存和生成效果尚未验收**。用户已允许必要的付费验证；后续真实生成使用 4 秒、480p，输入参考音视频尽量使用 2 秒的合格素材，不沿用旧的 5 秒 / 720p 样例。

面试中应能说明：浏览器 blob 地址只用于临时预览；OSS 存文件，数据库存归属 / 元数据 / 引用；引用保存 ID，提交任务时才固定资源 Key 快照；浏览器能播放与供应商能接受是不同边界；前端负责反馈，后端负责可信校验。此阶段可据实介绍音频上传与混合引用，不能描述为全模态视频生成已完整上线。
