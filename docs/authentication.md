## 用户流程与范围

- 邮箱不设服务商白名单，按常规邮箱地址格式和长度校验。平台账号匹配不区分大小写，保留 `+` 和点号，不做厂商特定的别名合并。这是平台的账号规则，不代表所有邮件服务器的收件规则。
- 邮箱仅为未验证的登录标识，`email_verified_at` 保持空值。格式正确不能证明邮箱属于操作者；输错未注册邮箱会创建新账号。此版本不能直接把邮箱用于找回密码或认定真实身份。
- 登录与自动注册的密码均为 6～20 个 Unicode 字符（按码点计数），不能全为空白。前后端分别校验；超出范围提示错误，不截断输入、不去除首尾空格，支持粘贴、密码管理器和显示/隐藏。此调整不修改已有密码哈希；旧密码若超过 20 个字符，重新登录时也会被新规则拒绝。
- 已有邮箱密码错误、账号禁用均不创建新用户、不覆盖旧密码。统一返回认证失败。
- 页面明确提示新邮箱自动注册并获赠 200 测试积分，以及暂不支持找回密码。

```text
浏览器提交邮箱和密码
→ Gin 检查来源、请求大小、账号/IP 限流
→ identity 规范化账号、验证密码输入
→ persistence 查询用户
  ├─ 已存在：验证 Argon2id 密码哈希及账号状态，不再赠分
  └─ 不存在：创建用户、200 分积分账户和唯一 grant 流水；邮箱唯一约束处理并发注册
→ 同一 PostgreSQL 事务创建登录会话并提交
→ Set-Cookie 写入随机会话凭证
→ Vue 加载“我的画布”，按登录用户读取 /api/credits 并显示余额
```

新用户、200 分积分账户、一条 `grant` 流水与首个 Session 在同一事务中提交；任一写入失败时整笔事务回滚，不会留下已注册却未获赠的账号。赠分流水使用按用户 ID 生成的唯一幂等键，不因重复请求或重新登录多发。两个不同密码并发注册同一邮箱时，只允许先成功创建的密码登录；另一个请求读取已有用户后验证其密码，也不赠分。事务内不调用邮件、模型或 OSS。

## Session 与接口

使用服务端 Session，不使用 JWT 或 Refresh Token。随机会话凭证为 32 字节加密随机数，浏览器通过 HttpOnly Cookie 携带；数据库只保存 SHA-256 凭证哈希。密码使用独立的 Argon2id 算法，19 MiB 内存、2 次迭代、独立随机盐。

| 接口 | 契约 |
| --- | --- |
| `POST /api/auth/login` | JSON `{email,password}`；新建或登录都返回 200 `{user:{id,email,role},csrfToken,expiresAt}`，并设置 Cookie；role 字段随管理端扩展加入 |
| `GET /api/auth/me` | 返回当前用户、会话 CSRF Token 和绝对到期时间；无有效会话返回 401 |
| `POST /api/auth/logout` | 撤销当前会话，清除 Cookie，返回 204；其他设备的独立会话不受影响 |

登录请求需 `X-Requested-With: frame-space` 和受信任的浏览器 Origin（缺失时检查 Referer）。其他写请求需来源验证和该会话的 `X-CSRF-Token`。CSRF Token 不是登录凭证，也不是 Refresh Token。未登录业务请求返回 401；数据库未配置/不可用返回 503，不能降级成匿名生成或读取。

Cookie 为 host-only、Path=/、HttpOnly、SameSite=Lax。正式 HTTPS 使用 Secure 和 `__Host-frame_session`；本机 HTTP 使用 `frame_session`。前端不把会话凭证放进 localStorage 或 URL。

会话空闲期限 24 小时、绝对期限 7 天。已通过认证与 CSRF 检查的业务写请求可延长空闲期限，每 5 分钟以内不重复写续期；绝对期限不延长。任务轮询、素材读取、`/me` 不续期。过期/撤销会话不能恢复，需要重新输入密码。每次登录生成新凭证。

登录限流目前位于单个 Go 进程：每 IP 每 15 分钟 40 次，每邮箱 12 次；密码哈希并发上限 4。返回 429 和 Retry-After。重启会重置计数，尚未实现分布式防刷。生成入口按用户的测试积分额度控制，见 [测试积分](./test-credits.md)；注册赠分对每个新账号仅执行一次。邮箱尚未验证，单进程限流也不能防止批量更换邮箱或 IP 领取测试积分。用户已选择暂不设置每日新账号总量上限；当前没有平台预算熔断，这两项不能视为已实施的防护。自动注册的成功/失败差异也可能被用于推测账号是否存在。

## 数据模型与权限

账号阶段新增 `users`、`user_sessions`，`canvases` 新增非空 `owner_user_id` 外键和用户/更新时间索引。用户表邮箱有唯一约束。用户状态为 active/disabled；管理端可查看状态，目前没有禁用／启用操作页面。2026-10-06 测试积分迁移另增加 `credit_accounts` 和 `credit_ledger`，通过用户外键隔离余额及流水；2026-10-08 注册赠分复用这两张表。随后管理端的 007 迁移增加用户角色和流水审计字段，不改变画布归属模型。旧账号没有注册赠分流水，登录不会自动补写。

```text
users
├─ user_sessions（一个用户可有多个设备会话）
├─ credit_accounts → credit_ledger（测试积分账户及流水）
└─ canvases.owner_user_id
   ├─ assets.canvas_id
   └─ generation_tasks.canvas_id
```

Gin 中间件从服务端会话取得 userId；Handler 检查画布、任务或素材的数据库归属。画布列表按所有者过滤，新建使用会话中的用户；保存 SQL 同时检查所有者和版本号。当前没有资源转让或共享，因此所有者不可通过 API 改变。

图片/视频提交包括已存在 taskId 的幂等返回路径，必须检查归属；参考素材继续检查是否在同一授权画布。素材读取先检查 `assets → canvases`，再访问 OSS，Range 请求同样受保护。未登记的 Key 和其他用户的资源统一拒绝。媒体响应为 `private, no-store`。

后台 Worker 处理已授权创建的任务，继续使用现有平台凭据；不依赖浏览器会话。用户退出或会话过期不会取消已受理生成。2026-10-05 已改为 PostgreSQL 持久化队列：默认视频并发 3、图片并发 1，超出等待，同一节点仍限制一个未完成任务。没有新增 Redis、独立消息队列或第三方身份服务，见 [生成队列](./generation-queue.md)。

## 前端状态

`App.vue` 启动先通过 `/api/auth/me` 恢复身份。根路径收到 401 时显示公开首页；访客点击登录或创建才进入登录表单。根路径遇到 503／断网仍显示静态公开首页和重试提示，不展示旧账号数据；画布深链遇到服务故障显示重试。画布深链在 401 时先显示登录页。`authFetch` 统一附加 CSRF 与 `X-Session-User`，后者仅用于检测跨标签页账号变化，实际身份始终由 Cookie 决定。

`credits.ts` 监听登录状态和用户 ID：认证成功后自动调用 `GET /api/credits`，切换账号或退出时先清除内存中的旧余额。界面只显示服务端返回的余额，不在前端执行赠分或计算账户总额。

401、会话用户不符或 CSRF 失效时隐藏当前工作区，停止自动保存和任务轮询，取消旧请求。首页卸载个人画布库，显示无账号信息的公开页；画布编辑页保留当前页面内存中的草稿。同账号登录后继续保存和查询；不会自动重新提交付费生成。画布页重新登录表单的邮箱锁定为原账号。BroadcastChannel 通知其他标签页隐藏旧内容。

退出前画布先保存，未上传本地文件需由用户选择是否离开；退出失败保留页面。主动退出会刷新到首页，清除内存状态。过期期间的未保存内容只保留在当前页内存，刷新或关闭标签页不能承诺恢复。

## 配置与本地启动

`backend/.env.local` 保持已有数据库/OSS/模型配置。新增可选配置见 `.env.example`：

```dotenv
APP_ORIGINS=http://127.0.0.1:5173,http://localhost:5173,http://127.0.0.1:5176,http://localhost:5176
AUTH_COOKIE_SECURE=false
```

APP_ORIGINS 是浏览器访问的来源，不能用代理后的 8080 地址替代。省略时允许本机 5173/5174/5176；正式站点需明确 HTTPS 来源并启用 Secure。后端仍仅监听 127.0.0.1，不是公网部署验收。

数据库启动仍使用根目录 `scripts/start-postgres-wsl.ps1`，然后在 backend 运行 `go run ./cmd/server`，frontend 运行 `npm run dev`。浏览器入口为 `http://127.0.0.1:5173`。
