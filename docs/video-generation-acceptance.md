## 1. 最小正向案例 M1：三个参考生成一个视频

目的：一次任务覆盖图片、视频、音频输入，供应商任务追踪、结果转存和节点展示。只用一个目标视频节点，先不测多角色、编辑、延长或复杂分镜。

| 项目 | 样例规格 | 当前准备状态 |
| --- | --- | --- |
| 画布 | 独立验收画布 | 第三步已创建，ID 见验收记录；执行 M1 时新建任务 |
| 图片节点 A / 图片1 | 自制彩色测试图 sample-image.png；960×540 PNG，54178 字节 | 已准备、上传和校验，不含真人 |
| 视频节点 B / 视频1 | 自制动态图形 reference-video.mp4；854×480，2 秒，24 fps，MP4 / H.264 / yuv420p，无音轨，283035 字节 | 已准备、上传和校验 |
| 音频节点 C / 音频1 | 自制节奏 reference-audio.wav；2 秒，WAV / PCM，48 kHz、单声道，192078 字节 | 已准备、上传和校验 |
| 目标视频节点 D | 新建空视频节点，依次选择 A、B、C | 混合引用已验证；第三步额外引用 MP3 验证另一种音频格式，执行三参考 M1 时移除该额外项并检查编号 |
| 输出 | Seedance 2.5，reference，4 秒，480p，16:9，MP4，有声，水印开启 | 按用户节省额度要求更新，尚未生成 |

素材均位于 `frontend/tests/fixtures/`，探测结果、SHA-256 和真实资源 Key 记录在 `frontend/artifacts/media-references-live.json`。输入参考采用合格的 2 秒短片段，输出采用 4 秒 / 480p；这些参数不同，不能混为同一时长。

固定提示词：

> 参考图片1的彩色几何图案、视频1的图形运动和音频1的节奏，生成一段全新的4秒抽象动画。镜头固定，色块清晰，运动平滑，不要字幕。

使用契约中的完整请求示例：先把占位 UUID 和 assetKey 换成实际画布、节点及上传结果。图片、视频、音频分别转换为 reference_image、reference_video、reference_audio；不能把图片当 first_frame，不能把音频只转换为 generate_audio=true 后丢弃参考。

### 后续执行顺序

1. 确认模型已开通、凭据有效、额度可用；准备上述三份素材。普通测试先通过，再按当时用户授权的调用次数与预算进入真实验证。
2. 创建并保存 A、B、C、D，上传 A/B/C。记录三个 Key 与真实媒体元数据，确认均在同一画布。
3. D 选择 A/B/C 并提交固定参数；记录本地 taskId。接口快速返回任务，不等最终 MP4 下载完才返回。
4. 后台只创建一次供应商任务，保存 providerTaskId；前端显示等待 / 生成 / 保存阶段。
5. 在等待时修改 D 的草稿，切换到其他节点，再刷新页面；不再次点击生成。任务继续使用原输入，仍回填 D。
6. 模型成功后转存 OSS，通过同源地址播放、暂停、拖动进度；再次刷新，确认从保存的资源恢复。
7. 记录工程结果和内容效果两组结论；一次失败后先查原因，不自动更换提示词、模型或 taskId 连续付费重跑。

执行器重启、网络错误和转存失败优先通过模拟故障验收，不为了覆盖故障额外创建真实付费任务。一次真实混合参考任务通过，只证明该样例可用，不能证明所有组合、最大数量、长视频或高并发均已验证。

### 通过标准

**工程链路全部通过，M1 才记为端到端通过：**

- 提交记录中的三类参考均存在，顺序和角色映射正确；创建供应商任务次数恰好为 1。
- 本地 taskId 与 providerTaskId 分开记录，输入快照与提交时一致；改草稿、切节点、刷新不造成第二次生成。
- 任务依次进入对应阶段；只有资源在 OSS 保存并在数据库登记后才显示本项目完成。
- result.asset.kind=videos、source=generated，归属 D；result.url 是本项目素材接口地址。刷新后的播放、暂停和进度拖动可用。
- 文件可解码，实际为 MP4；记录实际宽高、编码、帧率、精确时长和音轨，检查请求为 480p / 16:9，不只相信接口宣称。4 秒样例预期实际时长与 4 秒相差不超过 0.5 秒；这是项目样例阈值，不是供应商 SLA，超出需查原因。
- 输出含音轨且实际能听见声音，输入和输出文件不为空；成功落库后可从任务历史找到输入、结果和时间。
- 页面、日志和验收记录不包含模型密钥、参考签名地址或结果下载签名地址；页面退出后无须保留 blob 地址才能恢复。

**内容效果单独人工观察：**彩色几何图案、图形运动和声音节奏是否有参考痕迹，是否出现明显字幕 / 闪烁。写明实际偏差，不承诺逐帧、逐音复制。测试图只用于最小工程验证，不证明真实业务场景的生成质量。

| reference-audio.wav / mp3 | 第三步新增自制节奏；后端实测均为 2 秒 | 上传、播放和视频参考已通过，模型采用效果未验证 |

## 3. 在真实调用前完成的模拟验收

下列是完整生成功能的目标断言。第三步已覆盖 C04 的 UI 编号、C05/C06 的前端组合校验与后端单文件校验、C20 的音频上传 / 播放 / 旧功能回归，以及部分 C07 素材格式与归属检查；供应商请求、视频任务、恢复和转存等未实现部分仍待执行，不能据此将整张表标为通过。

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| C01 | 请求包含图片、视频、音频 | content 有三种 URL 对象及对应 role，参数来自任务快照 |
| C02 | 仅音频且 prompt 为空 | 本地接受；不发送空 text；2.5 的音频参考被保留 |
| C03 | references 为空、请求纯文本 | REFERENCE_REQUIRED；没有供应商调用 |
| C04 | 混合列表 image、video、image、audio | UI / 请求对应图片1、视频1、图片2、音频1，无错位 |
| C05 | 数量边界及超限：图片30/31、视频10/11、音频10/11 | 合法边界通过；超限拒绝。隔离数量测试时其他条件均合法 |
| C06 | 同类视频 / 音频总时长30 / 大于30秒；单段小于2 / 大于30秒 | 合法边界通过；超限在创建供应商任务前失败，不靠取整放行 |
| C07 | 跨画布、自身、重复节点 / Key、类型伪造、URL冒充Key、损坏媒体 | 均被后端识别，供应商创建次数为零 |
| C08 | 同taskId同输入并发重交；同ID更改输入；同节点另一个未完成任务 | 分别是原任务 / TASK_ID_CONFLICT / GENERATION_BUSY，最多一次供应商创建；其他节点可提交并持久化排队 |
| C09 | 给默认值与省略默认字段两种请求；generateAudio=false | 规范化输入一致的请求复用；false 在供应商请求中保持false |
| C10 | 前端未收到202但后端已建本地任务 | 用原ID查回任务；不发明第二个任务ID |
| C11 | 供应商已受理但创建响应丢失；或返回ID后落库前进程退出 | interrupted / SUBMISSION_UNKNOWN，无自动再次创建 |
| C12 | 已保存供应商ID后重启；GET查询网络失败或429 | 查原ID；按策略恢复 / 退避，本地保持running，显示查询异常提示 |
| C13 | provider queued变running，本地仍running | updatedAt变化能更新界面；不能因status相同就忽略 |
| C14 | 供应商明确失败、expired、cancelled、任务类型不匹配 | 正确失败终态和可理解的脱敏原因，不自动切换模式或重新生成 |
| C15 | 供应商成功后OSS失败；重复点击重新保存 | storage_failed，可按原ID重试；再次转存成功，供应商创建计数保持1 |

| C18 | 提交后改草稿、来源换成新Key、切面板、刷新、旧结果迟到 | 原任务输入固定；原目标可恢复；旧任务结果不覆盖该节点的新任务 |
| C19 | 没有数据库 / OSS / 模型配置 | 明确提示不可生成；不进入临时视频生成模式 |
| C20 | 回归图片生成、旧画布 / 图片任务、音频普通上传和视频播放 | 旧数据仍可恢复，音频不能误入图片参考，无密钥泄露 |

C05 的10段视频或音频可各2秒，合计20秒；不能为了测数量上限而无意触发总时长上限。上限覆盖先用合格元数据与本地模拟供应商，不做30张图片、10视频、10音频的真实昂贵调用。

## 4. 证据与停止条件

后续验收证据建议写入被 Git 忽略的 `frontend/artifacts/video-reference-live.json`，截图使用同前缀 PNG。**本轮没有创建这些证据文件。** 记录：

- 验收时间和代码版本；真实或模拟环境；模型 ID、最终请求参数。
- 三份素材的来源、SHA-256、元数据、资源 Key、分类编号，不存签名 URL。
- 本地 / 供应商任务 ID、阶段时间、供应商创建次数、返回用量（如果有）。
- 结果资源 Key、精确媒体信息、浏览器播放 / 刷新恢复结论。
- 工程验收与内容观察分开；实际调用费用只在有账单证据时填写，不用推算冒充扣费。

出现以下任一情况，停止下一次付费提交，先报告已知结果、原因及所需信息：

- 未开通模型、额度不足或凭据不具备权限；不能自动充值或改用其他模型。
- 素材不合格、方舟无法读取、出现权限或输入限制；不能不断重新生成试错。
- 创建结果不确定、拿到供应商ID但未可靠保存；先核查已有任务。
- 官方资料与实际响应冲突，影响参数语义、结果读取或计费边界。

第一步完成标准：接口字段、错误 / 恢复边界、媒体映射和 M1/N1 的通过标准均有可评审文本；示例 JSON 可解析且自洽，项目地图能找到文档。**不以本步骤完成推导出音频已支持、接口已上线或视频已生成。**
