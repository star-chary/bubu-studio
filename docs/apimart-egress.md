# APIMart 出站连接排查与线上方案

2026-10-29：线上服务器对 `api.apimart.ai` 的 DNS 解析结果与本机及公共 DNS 不同；使用公共 DNS 返回的地址测试时，TCP 可连接但 TLS 握手被重置。本机相同图片型号与参数可以完成生成。线上图片任务提交约 30 秒后中断，图片适配器没有记录原始网络错误，因此不能仅凭任务记录断定供应商一定没有受理。

在用户授权的临时测试中，线上服务器使用本机现有的两条外部线路，分别通过 TLS 校验和使用线上密钥访问 APIMart 模型列表；每条线路连续两次返回 200。另用一个不可达的主线路和一条真实备用线路测试自动切换：备用线路被选中，模型列表返回 200。上述请求只读取模型列表，没有生成媒体。当时的测试配置保存在服务器临时内存目录，测试后进程退出且配置已删除。

服务器临时测试了代理目的地限制：APIMart 模型列表认证请求返回 200，其他域名请求被拒绝；测试配置与进程随后清理。

使用经过官方发布摘要校验的 Mihomo 版本进行服务器临时测试。首次以 systemd 凭据方式启动时，配置源放在 `/dev/shm`，凭据阶段失败；改用 `/run` 受限临时目录及另一临时二进制路径后，动态用户、隔离服务和凭据加载测试通过，认证读取模型列表返回 200。临时服务、二进制和配置随后均已清除。

当前线路来自用户电脑上的本地静态配置，没有可识别的自动更新地址或有效期信息。短时连通和备用切换不等于长期稳定：线路运营方、凭据变化、续费和出口可用性仍需持续管理。

## 请求路径与提交保护

本地后端支持可选环境变量 `APIMART_PROXY_URL`。留空时沿用原有默认传输；配置时只允许不含凭据、路径和查询参数的本机 HTTP 代理地址，例如 `http://127.0.0.1:18797`。无效配置使后端启动失败，避免错误配置被默默忽略。

```text
APIMart 图片 / 视频提交与轮询
→ 后端专用 HTTP 客户端
→ 本机 HTTP 代理（配置时）
→ 外部线路
→ 保留 TLS 证书校验 → APIMart
```

该配置只作用于 APIMart 客户端，不改变方舟、OSS 或进程级代理设置。代理不可用时，客户端不会切换到直连，也不会自动重新提交生成任务。供应商返回的媒体下载仍使用原有独立下载器和公网地址校验；此前对一个历史图片结果域名的根路径验证了线上 TLS 可达，但没有读取真实生成文件，不能代表全部图片、视频结果域名都可下载。

本地测试覆盖图片和视频提交／轮询经过 HTTPS 代理、代理不可用时不直连，以及代理地址校验。[常驻服务模板](../deploy/systemd/frame-apimart-proxy.service)使用动态用户和 systemd 凭据；[线路配置示例](../deploy/mihomo/apimart-proxy.example.yaml)只含占位符，通过未经认证的模型列表请求检查备用线路，不包含真实线路凭据。

本地版本进一步将生成提交与只读轮询分开：生成提交使用不可重放的请求体、不跟随重定向、不复用连接并使用 HTTP/1.1；网络错误或无法识别的响应保留 `SUBMISSION_UNKNOWN`，不会自动重新提交。模拟测试覆盖线路 A 已收到请求但响应丢失、此后新连接切至线路 B 的情形：原任务只提交一次，新任务可使用 B。只有可识别的供应商明确拒绝才按拒绝处理；其余不明确响应保留积分核查状态。服务在提交中重启的数据库测试验证了不重新提交和保留积分。

节点收到 `SUBMISSION_UNKNOWN` 时展示再次点击会创建新任务、可能产生费用的提醒；本地浏览器模拟测试验证刷新后提醒仍可见。网络失败日志只记录任务 ID、网络阶段、分类和耗时，不记录凭据、提示词、签名地址或供应商原始响应。网络阶段仅用于排查，不能据此认定供应商是否受理或自动重发。

## 2026-10-29 线上部署与边界

- 用户授权使用现有线路及其流量，并将所需线路配置保存在自己的服务器。生产版本切换到 `/opt/frame-space/releases/20261029T081908Z`，后端与前端构建源提交为 `4d1d9550563886a9c9dd5b8202527cac09f84681`。发布前备份了数据库和后端环境配置，并校验数据库备份可读取；上一个应用版本保留。
- `frame-apimart-proxy.service` 已启用开机启动并处于运行状态；经过摘要校验的 Mihomo 安装在 `/opt/frame-space/bin/mihomo`。真实线路配置位于 root 持有、权限为 `0600` 的 `/etc/frame-space/apimart-proxy.json`，由 systemd 凭据机制提供给动态用户。代理只监听 `127.0.0.1:18797`，只允许 `api.apimart.ai`，其他目的地的 TLS／HTTP 连接在测试中被拒绝。后端已启用 `APIMART_PROXY_URL`，其他供应商与 OSS 沿用原路径。
- 部署前两条候选线路分别连续两次通过带线上密钥的只读模型列表请求；部署后常驻代理同样返回 200。另从生产配置创建隔离临时实例，让主线路不可达，备用线路成功完成只读请求。代理每 300 秒检查线路；这是线路选择检查，不是对供应商任务是否已受理的判断，也没有配置外部故障通知。
- 首次上线尝试的限制检查仅检查 CONNECT 是否被应答，不能判断后续目标 TLS 是否被拒绝，因此触发自动回滚。随后通过隔离实验确认其他目标的 TLS／HTTP 请求被拒绝，修正检查后重新部署；回滚期间原服务正常，业务任务和待核查积分未被改动。
- 部署及验收均未调用收费生成接口。模拟测试验证了线路切换后不重发、服务重启后保留待核查积分，浏览器模拟测试验证了费用提示；已部署前端和后端的线上健康检查、鉴权边界、文件摘要与只读代理检查通过。尚未验证本次生产版本的真实图片／视频生成及供应商结果转存，不能把只读检查当作生成成功。

线路配置副本已保存在服务器，服务运行不依赖用户电脑开机。这些配置是静态的，不会自动续订或同步线路变更，两条线路也可能同时失效或受同一运营方故障影响；需要定期确认线路仍可使用并安全更新服务器配置。若线路不可用，提交结果仍可能进入 `SUBMISSION_UNKNOWN` 和积分核查，不能自动重新提交或解冻。部署时确认的 4 条待核查任务共 854 积分，仍须根据供应商记录核实，不能因为网络恢复而自动释放。
