使用经过官方发布摘要校验的 Mihomo 版本进行服务器临时测试。首次以 systemd 凭据方式启动时，配置源放在 `/dev/shm`，凭据阶段失败；改用 `/run` 受限临时目录及另一临时二进制路径后，动态用户、隔离服务和凭据加载测试通过，认证读取模型列表返回 200。临时服务、二进制和配置随后均已清除。服务模板经过语法校验，尚未按实际生产安装路径启动。

当前线路来自用户电脑上的本地静态配置，没有可识别的自动更新地址或有效期信息。短时连通和备用切换不等于长期稳定：线路运营方、凭据变化、订阅续费和出口可用性仍需持续管理。若使用已有线路作为长期出口，须先明确用户授权、凭据的服务器存放方式、线路更新与失效后的处理方式。

## 本地准备的请求路径

本地后端支持可选环境变量 `APIMART_PROXY_URL`。留空时沿用原有默认传输；配置时只允许不含凭据、路径和查询参数的本机 HTTP 代理地址，例如 `http://127.0.0.1:18797`。无效配置使后端启动失败，避免错误配置被默默忽略。

```text
APIMart 图片 / 视频提交与轮询
→ 后端专用 HTTP 客户端
→ 本机 HTTP 代理（配置时）
→ 外部线路
→ 保留 TLS 证书校验 → APIMart
```

该配置只作用于 APIMart 客户端，不改变方舟、OSS 或进程级代理设置。代理不可用时，客户端不会切换到直连，也不会自动重新提交生成任务。供应商返回的媒体下载仍使用原有独立下载器和公网地址校验；此前对一个历史图片结果域名的根路径验证了线上 TLS 可达，但没有读取真实生成文件，不能代表全部图片、视频结果域名都可下载。

本地测试覆盖图片和视频提交／轮询经过 HTTPS 代理、代理不可用时不直连，以及代理地址校验。[常驻服务模板](../deploy/systemd/frame-apimart-proxy.service)使用动态用户和 systemd 凭据；[线路配置示例](../deploy/mihomo/apimart-proxy.example.yaml)只含占位符，通过未经认证的模型列表请求检查备用线路，不包含真实线路凭据。两者只是待部署准备。

该代码尚未发布生产；要上线还需核对常驻代理服务的安装、受保护的线路凭据、健康检查、回退方案和实际生成／转存验收。当前候选线路没有已知的自动更新来源，不具备自动续订或自动同步线路变化的能力；需要明确线路维护人和失效处理方式。历史 `review` 积分需先核对供应商记录，不能因为网络恢复就自动解冻。

## 待核对的上线方案（尚未执行）

1. 获取用户对线路配置长期保存在自己服务器、消耗该线路流量的明确授权；重新测试候选线路，不能仅依靠临时测试时的顺序或一次成功。
2. 核对当前版本、生成任务、端口和系统空间，按现有发布流程备份数据库和后端环境配置；不在有活动生成任务时切换后端。
3. 核对官方代理程序的发布版本与摘要；安装独立服务。真实线路配置只存放于 root 持有的 `/etc/frame-space/apimart-proxy.json`，由 systemd 凭据机制提供给动态用户，不写入代码、日志或前端。服务仅监听 `127.0.0.1:18797`，只转发 `api.apimart.ai`，拒绝其他目的地；使用两条候选线路和未认证的模型列表请求进行备用切换。
4. 部署已验证的新后端，设置 `APIMART_PROXY_URL=http://127.0.0.1:18797`；仅在确认代理可用后切换后端，并核对运行程序摘要、健康接口及既有应用入口。
5. 使用线上密钥执行只读模型列表检查，另检查结果下载和已有功能；真实生成会产生费用，须在明确授权后进行单次端到端验收，不能把只读检查当作生成成功。原有待核查任务不重新提交或自动解冻。

若启动或验证失败，按备份恢复原后端版本和环境配置，停止本次新增的代理服务；保留业务数据库和媒体。上线后仍需处理静态线路没有自动更新来源的问题，不能把双线路切换误称为对供应商或订阅失效的保证。
