# PostgreSQL 持久化生成队列

更新：2026-10-05。已移除图片、视频合计只能有一个活动任务的限制。不同用户、不同画布、不同节点可以同时提交，接口保存任务后返回 202，后台按名额执行，超出的任务留在数据库等待。模型和 OSS 验证使用模拟实现，不新增付费调用。

## 请求与数据流

```text
用户点击生成
→ Session / CSRF / 画布与素材归属校验
→ 校验参数、固定任务输入及参考素材快照
→ generation_tasks 写入 queued，返回 taskId
→ 执行槽通过 PostgreSQL 原子领取任务
→ preparing：读取并检查参考素材，临近提交时才生成签名地址
→ submitting（视频）/ running（图片）：调用模型
→ running：视频继续查询同一个 providerTaskId
→ saving：保存供应商结果，释放生成槽
→ 独立转存槽下载、校验、存 OSS
→ 事务登记资产并完成任务
→ 浏览器轮询，刷新后恢复对应账号、画布、节点的状态
```

## 并发与边界

| 配置 | 默认值 | 范围 / 含义 |
| --- | --- | --- |
| `VIDEO_GENERATION_CONCURRENCY` | 3 | 1–3；所有用户共享，准备素材、提交、供应商排队及查询期间占用 |
| `IMAGE_GENERATION_CONCURRENCY` | 1 | 1–16；独立图片执行额度，默认保守使用 1，调整前核实图片模型配额 |
| `ASSET_SAVE_CONCURRENCY` | 2 | 1–4；图片和视频结果转存共享，避免多个大视频同时占用临时磁盘和带宽 |

配置缺失使用默认值，非法值拒绝启动；修改后重启后端。设置示例在 `backend/.env.example`。视频 3 个是本项目的调度上限，不代表供应商必然立即处理 3 个；同一供应商账号在其他应用的使用仍可能消耗配额。供应商排队状态继续单独展示。

默认情况下，10 个用户各提交一个视频任务都可保存，3 个进入执行，其余等待；释放一个槽就领取下一个，不需要等一批全部结束。图片不会因视频 3 个槽已满而被拒绝。生成完成、等待或执行转存的任务不占生成槽。

同一个节点只允许一个未完成任务（包含排队与转存）；其他节点不受影响。重复提交相同 taskId 和输入返回原任务；同 ID 改输入返回冲突。同节点用新 ID 重复生成或重试旧视频保存时，若已有未完成任务，返回 409 `GENERATION_BUSY`，提示该节点已有任务。

等待任务按创建时间、ID 领取，已提交供应商的 running 视频优先恢复；不保证不同任务的完成顺序。当前未实现用户优先级、每用户运行配额、队列长度上限、取消排队或计费额度。仍是同一数据库 schema 的单个后端调度器，尚未支持多个后端同时消费；不同数据库 / 部署不会自动共享同一供应商账号额度。

## 数据库与领取机制

005 迁移沿用 `generation_tasks`，没有新增队列表、Redis 或消息队列服务：

- 删除全表常量唯一索引 `generation_one_active`。
- 新增 `(canvas_id,node_id)` 上的部分唯一索引 `generation_node_active`，仅约束 queued / preparing / submitting / running / saving。
- 增加 `claimed_at` 标识已由执行槽领取，新增队列检索索引及 preparing 状态。
- CTE + `FOR UPDATE SKIP LOCKED` + `UPDATE ... RETURNING` 在同一条 SQL 中完成选取、锁定、记录领取状态。竞争者跳过被锁住的行，不能同时领取同一个任务。
- 锁只覆盖短暂的领取事务；外部模型、媒体读取、轮询和 OSS 网络操作不占用数据库事务。

数据库会话 advisory lock 保留，用来保证同一 schema 只有一个调度器和一个恢复入口；该调度器内部可同时运行多个执行槽。正常退出先取消并等待全部槽结束，再释放锁。锁连接丢失时停止调度及 HTTP 服务；恢复数据库后重启。

## 重启与重试

| 中断时状态 | 恢复行为 |
| --- | --- |
| queued | 数据仍在队列，继续等待领取 |
| preparing | 尚未调用付费模型，释放旧领取标记并回到 queued |
| 视频 submitting | 无法确认供应商是否受理，标 interrupted，不自动重交 |
| 视频 running | 按原 providerTaskId 继续查询，绝不重新创建 |
| 图片 running | 沿用原策略，标 interrupted，不自动重跑付费生成 |
| saving | 仅恢复转存，不调用生成接口 |
| 视频 storage_failed | 用户重试后回到 saving，由转存槽处理 |

供应商查询窗口按视频实际提交时的 started_at 计算，本地排队时长不计入；旧记录缺少该时间时兼容使用 created_at。供应商提交超时 / 5xx 的不确定状态、明确限流拒绝等仍沿用现有错误策略，不盲目重新创建付费任务。
