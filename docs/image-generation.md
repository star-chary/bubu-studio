# 图片生成：文生图与图生图

更新：2026-09-24。Lite / Pro 均已接通参考图输入，固定单张、2K 请求规格、保留水印。现已接 PostgreSQL 后台任务、生成历史和画布恢复，详见 [持久化说明](./persistence.md)。此前 Lite 真实图生图 / OSS 转存已验证；Pro 图生图及多参考仍为模拟验证。本次数据库阶段未新增付费模型调用。

## 使用方式

上传图片并等待“保存中…”消失、确认没有保存失败提示 → 新建图片节点 → 点击“参考”选择素材 → 输入编辑要求 → 选择模型并生成。也可参考已成功转存的生成图片。面板编号对应模型的参考图顺序，可在提示词中使用“图一”“图二”。结果回填当前目标节点，保留连线和原素材；没有参考时沿用文生图。

保存中、失败、未保存或源节点仍在生成 / 加载时禁止提交，并说明原因。Lite 最多 14 张参考，Pro 最多 10 张，切换模型后立即重新检查。参考图数量不等于输出数量，当前始终只生成一张。

## 实际流程

```text
前端 referenceIds 按顺序解析为来源节点的 asset.key
 → 点击生成时固定提示词、模型、目标 ID、referenceKeys 快照
 → POST /api/images/generations
 → Gin 校验输入，写 PostgreSQL queued 任务并返回 202 + taskId
 → 图片执行槽领取并准备素材，写 running；其他任务持久化排队（同节点仅一个未完成任务）
 → Storage 检查同画布、其他节点、图片路径和重复输入
 → 读取私有 OSS 图片头，检查实际格式、大小和尺寸
 → 签发每张图片 10 分钟有效的 OSS GET 地址
 → Ark Client 将地址列表作为 image 参数交给方舟
 → 模型读取参考图，返回单张结果的临时地址
 → 记录模型结果与 saving 状态，再下载保存到 generated/images
 → 事务登记资源与 succeeded 任务，前端查询后在原节点展示
```

签名 URL 让模型临时读取指定私有文件，不需要公开整个桶。它只在后端与模型之间使用，不返回前端，不写入日志或验收记录。浏览器的 `blob:` 和本机预览接口无法被云端模型读取，前端因此提交资源 Key，由后端转换。

`referenceIds` 是当前编辑关系，`generation.referenceKeys` 是已提交的资源快照。等待期间修改提示词、模型或参考只影响下次请求；来源重新生成会分配新 Key，已提交的旧文件保持可读。连线不是自动执行的任务依赖，修改来源不会自动触发目标生成。

## 接口与约束

继续使用 `POST /api/images/generations`；数据库模式增加必填 UUID `taskId` 并返回 202 任务对象，原 `prompt/model/canvasId/nodeId/referenceKeys?` 保持。省略参考或空数组为文生图，有值为图生图。资源需已登记到当前画布，只接受当前环境内其他图片节点的完整 Key；不接受任意 URL、Base64 或模型密钥。未配置数据库的临时模式仍返回同步 200 图片结果。

图生图要求 OSS 已启用、参考素材已保存。本期支持 PNG、JPEG、WebP、GIF、BMP，单张不超过项目上传限制 20 MiB。前后端都检查宽高大于 14 像素、宽高比 1:16～16:1、总像素不超过 3600 万。后端用 Go 图片解码器读取最多 1 MiB 文件头，不分配完整像素缓冲；异常或过大的头部会提示转换为 PNG/JPEG。AVIF 可以上传预览，但不作为本期模型参考。

参数依据[官方图片生成 API](https://docs.volcengine.com/docs/ark/image-generation-api?lang=zh)：参考图使用 `image` 数组；Lite 显式 `sequential_image_generation=disabled`，Pro 省略不支持的组图和流式参数。后端只接受恰好一个结果，前端不提供数量控件。OSS Go SDK V2 使用 `Presign(GetObjectRequest, PresignExpires(10*time.Minute))` 签发地址。

参考准备最多 30 秒，模型最多 180 秒，转存最多 90 秒。数据库模式生成名额覆盖 queued/running/saving，前端每 2 秒查询任务，刷新不会取消后台任务；模型不自动重试。后端在 running 期间重启时标记 interrupted，saving 状态只继续保存结果。旧临时模式仍保留前端 315 秒和代理 330 秒长请求。

## 失败与验证

- 参考无效、超限或读取失败：在调用模型前拒绝。
- 模型失败：保留已有结果和草稿，允许用户修正后再次提交。
- 生成成功但转存失败：返回临时图片与保存失败提示，不重新调用模型。
- 数据库模式刷新恢复节点 / 关系和任务，未上传成功的本地文件显示重新上传提示。没有登录，画布路径校验不替代所有权鉴权。

后端测试覆盖模型单图参数、参考顺序、数量上限、无效路径 / 类型 / 自身 / 跨画布 / 重复参考、尺寸、签名有效期、前置失败不调用模型、签名不透传。原有 33 项全量浏览器回归通过；补充模型数量边界后，图生图专项 4 项通过。Go 测试、vet 和前端类型检查 / 构建通过。

真实验收：2026-09-23 23:03（北京时间），Lite、1 张参考、1 次模型请求，约 30.7 秒返回 2848 × 1600、402,260 字节的 JPEG。参考读取、结果转存、结果读取及画布展示均成功。结果保留色条和斜线构图，并变为柔和颜色及水彩纹理。证据为被 Git 忽略的 `frontend/artifacts/image-to-image-lite-live.json` / `.png`，本次保留一份测试参考图和一份生成结果。

复验脚本 `frontend/scripts/verify-live-image-to-image.mjs` 要求显式设置 `RUN_LIVE_GENERATION=1`、`RUN_LIVE_STORAGE=1`，可选 `LIVE_IMAGE_MODEL=lite|pro`；每次只提交一次生成，失败不自动重试。普通回归不调用真实云服务。
