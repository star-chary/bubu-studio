## 用户操作与数据流

```text
视频节点选择模型、生成类型、时长、画质、比例及声音
→ 节点草稿保存 videoModel / videoMode / videoOptions
→ 前端用同一份输入请求 /api/credits/quote
→ 后端检查画布、节点、参考资源归属及模型规则，并返回积分与价格版本
→ 提交任务时后端重新核价，在同一数据库事务中冻结积分、保存输入快照和排队任务
→ 后台按模型重新读取并检查真实参考文件；文生视频不读取参考文件
→ 后端使用平台方舟账户创建和查询任务
→ 成功转存到 OSS 并登记资源后结算积分；明确失败退回，不确定结果保留冻结待核查
```

文生视频必须有非空提示词，请求不带 `references`，提示词中的 `@` 素材标签也不能提交。切到文生视频时，画布上原有参考连线作为草稿保留，界面明确提示本次不会使用；切回全能参考后可继续编辑。全能参考至少需要一项合格素材，提示词可为空。切换到较短时长模型时，节点时长会收敛到新模型上限；已连接而超出新模型限制的素材不会偷偷删除，报价和生成会显示原因并阻止提交。

2.5 的全能参考请求带 `omni_reference_task_type=reference` 和 `output_format=mp4`；2.0 系列省略这两个仅适用于 2.5 的字段。纯文生视频只发送文本内容。当前全能参考表示参考素材生成新视频；编辑和延长输入视频属于其他任务类型，未作为当前功能承诺。[方舟创建任务 API](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh)

旧画布若没有 `videoModel` / `videoMode`，按 Seedance 2.5／全能参考读取，已提交任务继续保留当时的模型、参数和积分价格版本。模型及生成类型存于现有画布快照，任务输入和积分冻结使用既有表，本次没有新增数据库表或迁移。浏览器只接收本项目任务状态和最终资源地址，不接收方舟密钥或可长期访问的供应商下载地址。

## 积分报价

价格版本 `test-2026-10-07-v2`。仍按 `2 × 向上取整(12 × 预估人民币成本)` 报价，采用[方舟常规刊例价](https://docs.volcengine.com/docs/ark/model-pricing?lang=zh)；未采用 2.0 fast／mini 的限时优惠。下表为 **16:9、5 秒、无输入视频** 的例子；是否有图片或音频参考，不改变该表的“无输入视频”档位。

| 模型 | 480p 测试积分 | 720p 测试积分 |
| --- | ---: | ---: |
| Seedance 2.5 | 82 | 182 |
| Seedance 2.0 | 56 | 120 |
| Seedance 2.0 fast | 46 | 96 |
| Seedance 2.0 mini | 28 | 60 |

含输入视频时按另一档单价、输入视频时长和最低 token 用量估算；`adaptive` 按该画质可能的最大面积估算，避免低报。报价是平台积分规则，不等于方舟最终账单。方舟说明准确 token 用量以任务结果的 `usage.completion_tokens` 为准，当前尚未建立真实账单对账样本；后续应在真实验收时核对估算与账单，再发布新价格版本，不能追改旧任务。[方舟定价与最低用量说明](https://docs.volcengine.com/docs/ark/model-pricing?lang=zh)

## 验证边界

后端在独立 `frame_space_test` 数据库内运行 `go test -count=1 -timeout 180s ./...` 全包通过，覆盖模型参数、请求体、报价、参考规则和 HTTP 链路；`go vet ./...` 通过。前端 `npm.cmd run build` 通过，Playwright 以 4 个 worker 全量运行 89/89 通过。首轮默认 8 个 worker 时 88/89，唯一失败为既有上传菜单测试超时；该项单独复跑和 4 worker 全量复跑均通过。浏览器测试使用模拟接口，能核对发送的模型、模式、积分与参考字段，不能证明账户已开通模型或真实生成可播放。本轮没有发起真实付费生成。
