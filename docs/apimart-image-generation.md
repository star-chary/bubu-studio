## 使用和数据流

在图片节点选择 APIMart 型号、输入提示词和基础参数；需要图生图时，先上传并保存参考图片。点击生成后：

```text
画布保存模型和参考 → 前端固定本次参数及输出节点
→ POST /api/credits/quote → 页面显示本次总积分
→ POST /api/images/generations（Session、CSRF、画布归属、报价复核）
→ 事务冻结积分，generation_tasks 保存供应商、价格、参数和素材绑定
→ 图片执行槽核验并签发参考图片地址 → APIMart 异步提交一次
→ 保存供应商任务 ID、查询原任务 → saving 转存到现有 OSS
→ assets 和任务结果入库 → 前端回填图片，刷新后恢复
```

继续使用 `canvases.snapshot`、`generation_tasks`、`assets` 和积分账户／流水，不新增表或迁移。新的 APIMart 图片任务按固定报价冻结和结算平台积分；2026-10-28 之前的 `legacy` 任务不追补扣分。中转站实际调用仍可能扣除中转站余额。历史方舟图片及其积分规则保留。

其他图片模型选择多张时，平台为每张创建独立节点并提交独立任务，供应商每次请求的 `n` 为 1。批量提交发生错误时停止提交后续任务，已接收的任务继续执行；用户需查看任务状态，避免重复生成。Nano Banana 2.1 的 2 / 4 张使用下述单次多图请求。Midjourney 已从新任务菜单隐藏；历史任务使用的四宫格结果展示逻辑保留。

线上开放 9 个 APIMart 图片模型；模型及参考图数量上限由前后端共享的 `backend/internal/apimart/image_models.json` 约束，价格与开放范围来自 `billing_models.json`。Z Image Turbo 暂只开放文生图。Seedream 5.0 Lite 的自动比例需要参考图。素材还需满足项目存储限制及各模型的实际格式、尺寸要求；更严格的供应商限制可能导致任务失败。

Seedream 5.5 只接入普通生成，每次 1 张，支持非空提示词、最多 10 张参考图、1K / 1.5K / 2K 与常用比例；不传图层拆分或高级编辑参数。选自动比例时，后端将所选清晰度作为 `size` 档位发送并省略 `resolution`，以避免供应商的 `size: auto` 默认使用 2K。参考图沿用项目素材格式与单张大小上限；平台会将每张参考图费用计入固定报价，供应商最终按实际输出像素和输入图数量结算。

Nano Banana 2.1 支持 1、2、4 张和 1K / 2K / 4K。选 1 张使用 `gemini-nano-banana-2.1-ext`；选 2 或 4 张使用 `gemini-nano-banana-2.1`，一次上游请求返回多个图片地址。平台保留每张图的节点及任务记录，在同一数据库事务中建立主任务和子任务并冻结一次总积分；保存各图片到 OSS 后分别回填。所有图片成功保存才结算整批积分；返回数量不足或多余、地址无效、存储失败以及提交结果不明时保留待核查积分，不自动重发。最多使用 14 张参考图，单张不超过 20 MB；Ext 模式参考图合计不超过 50 MB。具体额度还受项目素材存储限制约束。

Muse Image 使用非空提示词，可选最多 9 张参考图，原始文件合计不超过 11 MiB。报价和创建任务前，后端按已登记素材的服务端大小校验总量，前端也提前提示超限；仍须满足项目既有参考图格式和尺寸约束。支持 `1:1`、`16:9`、`9:16`、`4:3`、`3:4`、`3:2`、`2:3` 和自动比例：自动时实际请求省略 `aspect_ratio`，无参考图为 1:1，有参考图时跟随其比例。每次仅生成一张，输出尺寸由模型决定，不发送清晰度参数。请求以平台任务 ID 作为 `Idempotency-Key`，依旧最多提交一次；提交结果不明时保留待核查状态，不自动重发。

参考图只能来自当前画布已登记的其他图片节点。后端检查实际文件并签发 2 小时临时地址，地址只用于中转站读取，不由前端提交。图片生成请求仅转发固定的基础字段；未展示的历史高级草稿仍保留在画布，但不传给供应商。

## 失败与恢复

提交超时、5xx 或没有可靠任务 ID 时记录 `SUBMISSION_UNKNOWN`，不自动重发；服务重启发生在提交过程中时也保留为待核查。已经拿到供应商 ID 的任务重启后继续查询同一个任务，不重新生成。查询暂时失败会退避重试；输出成功后独立进入素材转存槽。沿用现有图片策略：转存失败时保留临时图片并提示下载，重新点击生成会产生新任务，而不是重试保存。
