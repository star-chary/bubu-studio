## 用户操作与数据流

```text
画布选择模型、输入提示词和参考素材
→ 前端 POST /api/credits/quote 请求报价
→ 后端检查登录身份、画布／节点／参考素材归属，按有效输入计算积分
→ 前端显示本次积分及可用／冻结余额
→ 用户提交图片或视频生成，请求带上报价积分和价格版本
→ 后端重新核价，在一笔 PostgreSQL 事务中冻结积分、写入任务与冻结流水
→ 队列领取任务，后端使用平台方舟账户调用模型并保存结果
→ 成功持久保存且可交付：结算；明确失败：退回；结果不确定：保持冻结待核查
```

积分账户归属 `users`，与供应商账单是两套记录。`credit_accounts` 保存可用和冻结余额；`credit_ledger` 记录 `grant`、`reserve`、`settle`、`release` 及操作后余额，发放和任务操作使用唯一幂等键。`generation_tasks` 保存本次积分、价格版本和积分状态。旧任务标记 `legacy`，不追补扣分。没有向用户开放积分发放接口；新账号赠分由后端注册流程写入，旧账号的手动发放工具仅用于旧数据处理。

## 注册赠分

```text
新邮箱提交 POST /api/auth/login
→ 后端校验邮箱、密码及请求来源
→ PostgreSQL 事务插入 users（邮箱唯一）
→ 仅在用户行确实新建成功时，插入 credit_accounts（可用 200、冻结 0）
→ 插入一条 credit_ledger grant +200（幂等键 signup-welcome-v1:<userId>）
→ 同一事务插入 user_sessions 后提交，浏览器获得 HttpOnly Session Cookie
→ Vue 观察到已登录，GET /api/credits 显示服务端余额
```

如果赠分或会话写入失败，整个注册事务回滚；已有邮箱的登录分支不写入赠分。并发请求由邮箱唯一约束决定实际创建者，赠分流水的唯一幂等键再约束同一用户只记录一次。旧账号即使余额为 0，重新登录也不会补发；此前给唯一旧用户手动发放的 200 分不会重复发放。赠分只改变站内测试积分，不在方舟账户产生费用；用户实际提交生成任务时，后端才会调用平台的方舟账户。

账户余额更新、任务创建和冻结流水在同一事务中提交。余额不足时不创建任务，也不进入模型队列；数据库的条件更新阻止并发提交超出余额。相同 `taskId`、相同输入重复提交只返回原任务；不同输入复用 ID 返回冲突。价格调整不改变已创建任务的价格快照。

## 结算边界

| 情况 | 积分处理 |
| --- | --- |
| 已冻结、排队中或生成中 | 留在冻结余额，尚未最终消费 |
| 生成结果持久保存为平台资源并可交付 | 从冻结余额结算，产生 `settle` 流水 |
| 尚未调用供应商即失败，或供应商明确拒绝／明确失败 | 退回可用余额，产生 `release` 流水 |
| 提交／调用结果不确定、执行中断，或视频转存失败 | 任务积分状态改为 `review`，保留冻结，等待人工核查；本版没有自动解冻接口 |
| 图片只获得临时供应商 URL，未保存为平台资源 | 保留冻结并标记 `review`；供应商可能已经计费，等待核查 |

任务终态及积分结算／退回在同一数据库事务中更新；重复完成不会重复扣分或退分。视频 `storage_failed` 可以按既有流程只重试转存，不重新调用模型；成功保存后才结算。图片转存失败目前返回临时地址、保持积分冻结，没有同类的只重试保存入口。方舟是否已扣费与用户积分处理需分开核对。

## 接口与错误

所有接口要求有效 Session；写请求仍要求来源和 CSRF 校验。余额和流水只查询当前登录用户，不接受任意用户 ID。

| 接口 | 当前作用 |
| --- | --- |
| `GET /api/credits` | 返回 `{available,reserved}`；无账户记录时两项均为 0 |
| `GET /api/credits/ledger?limit=20&offset=0` | 返回 `{entries,hasMore}`；每页 1～100 条 |
| `POST /api/credits/quote` | 传 `kind` 和与生成相同的输入，返回 `{points,priceVersion}` |
| `POST /api/images/generations`、`POST /api/videos/generations` | 在原请求中增加 `acceptedPoints`、`priceVersion`；后端重新核价后冻结并入队 |

生成提交中的关键拒绝：`404 NOT_FOUND` 表示画布、节点、参考资源或任务不属于当前用户／不存在；`402 CREDITS_INSUFFICIENT` 表示可用积分不足；`409 CREDIT_QUOTE_CHANGED` 表示报价已变化，需重新确认。相同节点已有未完成任务等冲突仍返回 409。以上拒绝均发生在供应商调用前。前端会显示本次报价、余额和不足提示；服务端检查是最终约束，无法通过绕过按钮直接生成。
